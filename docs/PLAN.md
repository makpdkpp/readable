# readable — แผนพัฒนาเว็บนิยาย (ฉบับที่ 2)

> สถานะ: ฉบับที่ 2 ปรับตามคำตอบของ Maki แล้ว ยังไม่มีโค้ด
> วันที่: 27 พ.ย. 2026
> เครื่องหมาย **[สมมติฐาน]** = สิ่งที่ผมเดาไว้ ต้องยืนยัน
> เครื่องหมาย **[ต้องเช็ก]** = ข้อจำกัดทางเทคนิคที่ต้องทดสอบจริงก่อนตัดสินใจ

---

## 1. เป้าหมาย

เว็บแอปของเราเองสำหรับนักเขียนและนักอ่านนิยายภาษาไทย ใช้ ReadAWrite เป็นแค่ตัวอย่างว่าฟีเจอร์ประเภทนี้มีอะไรบ้าง ส่วนชื่อ แบรนด์ หน้าตา และดีไซน์จะทำขึ้นใหม่ทั้งหมด

- นักเขียน: สร้างเรื่อง เขียนตอน ตั้งเวลาเผยแพร่ ดูสถิติ
- นักอ่าน: ค้นหา อ่าน เก็บเข้าชั้นหนังสือ ติดตามนักเขียน คอมเมนต์ กดถูกใจ
- รันบน Cloudflare ทั้งหมด

### สิ่งที่ Maki ยืนยันแล้ว (27 พ.ย. 2026)
- **อ่านฟรีทั้งหมด** ยังไม่มีระบบเหรียญหรือขายตอน
- **ผู้ใช้ไม่เกิน 100 คน** ในช่วงแรก จึงเลือกโครงที่เรียบง่ายและใช้โควตาฟรีของ Cloudflare ได้
- **รับเนื้อหา 18+** แต่ต้องให้ **admin อนุมัติ** ก่อนเผยแพร่
- **Claude เป็นคนเขียนโค้ด** และเก็บโค้ดใน **GitHub**

## 2. Tech stack ที่แนะนำ

| ชั้น | ที่เลือก | เหตุผล |
|---|---|---|
| Runtime / Hosting | **Cloudflare Workers** (static assets ในตัว) | ตอนนี้ Cloudflare แนะนำ Workers แทน Pages สำหรับโปรเจกต์ใหม่ ได้ SSR, API และไฟล์ static ในที่เดียว |
| Framework | **React Router v7 (framework mode)** + TypeScript | รองรับ Cloudflare Workers โดยตรง มี SSR ทำให้หน้าอ่านนิยายติด Google ดี ใช้ไฟล์เดียวกันทำได้ทั้งหน้าเว็บและ API |
| UI | Tailwind CSS + shadcn/ui | เร็ว ปรับแต่งได้ ไม่ติดดีไซน์ของใคร |
| ตัวแก้ไขข้อความ (นักเขียน) | **Tiptap** (เก็บเป็น JSON แล้ว render เป็น HTML) | รองรับตัวหนา เอียง จัดกลาง รูปภาพ ขยายเพิ่มได้ เช่นโหมดนิยายแชท |
| ฐานข้อมูล | **Cloudflare D1** (SQLite) + **Drizzle ORM** | ถูก ไม่ต้องดูแลเซิร์ฟเวอร์ Drizzle มีระบบ migration และ type ชัด |
| ไฟล์ (ปก รูปในตอน รูปโปรไฟล์) | **R2** | ไม่มีค่า egress, อัปโหลดตรงจาก browser ด้วย presigned URL |
| ย่อขนาดรูป | Cloudflare Images (transform จาก R2) | ทำปกหลายขนาดอัตโนมัติ **[ต้องเช็ก]** ค่าใช้จ่ายเมื่อคนเยอะ |
| แคช | Cache API (KV ค่อยเพิ่มถ้าจำเป็น) | ผู้ใช้ไม่เกิน 100 คน D1 รับไหวสบาย ยังไม่ต้องมีชั้นแคชเพิ่ม |
| งานเบื้องหลัง | **Cron Triggers** (Queues ค่อยเพิ่มภายหลัง) | เผยแพร่ตอนที่ตั้งเวลาไว้ คำนวณอันดับรายวัน/สัปดาห์ ด้วยจำนวนผู้ใช้ขนาดนี้ส่งแจ้งเตือนตรงๆ ได้เลย |
| นับยอดวิว | เขียนลง D1 ตรงๆ | ผู้ใช้น้อย ไม่คุ้มที่จะเพิ่มความซับซ้อน ถ้าโตขึ้นค่อยย้ายไป Workers Analytics Engine |
| ล็อกอิน | **Better Auth** (ใช้กับ D1 ได้) | อีเมล/รหัสผ่าน, Google, Facebook, **LINE** (คนไทยใช้เยอะ) |
| กันบอท/สแปม | **Turnstile** | ใช้ตอนสมัคร ล็อกอิน คอมเมนต์ |
| อีเมล | Resend หรือบริการอีเมลของ Cloudflare **[ต้องเช็ก]** | ยืนยันอีเมล รีเซ็ตรหัสผ่าน |
| ค้นหา | D1 FTS5 ก่อน, ถ้าไม่พอค่อยย้ายไป Vectorize/Workers AI | ดูหัวข้อ "ภาษาไทย" ด้านล่าง |
| ชำระเงิน | ยังไม่ทำ (อ่านฟรี) | ถ้าภายหลังอยากเปิดขายตอน ตัวเลือกคือ Opn Payments (Omise) หรือ Stripe Thailand |
| Dev / Deploy | Wrangler, **GitHub** + GitHub Actions, Vitest + Playwright | Claude เขียนโค้ดและเปิด PR ให้ Maki ตรวจ เมื่อ merge แล้ว deploy อัตโนมัติ มี staging แยกจาก production |

### ทางเลือกอื่นที่พิจารณาแล้ว
- **Next.js (ผ่าน OpenNext)**: ใช้ได้ แต่การรันบน Workers ยังมีจุดต้องปรับเยอะกว่า React Router
- **Hono (API) + React SPA**: เบาและยืดหยุ่น แต่ SEO ของหน้าอ่านจะแย่กว่าถ้าไม่ทำ SSR เพิ่ม ถ้าภายหลังอยากทำแอปมือถือ สามารถแยก API ออกมาเป็น Hono ได้
- **Postgres ภายนอก (Neon/Supabase) ผ่าน Hyperdrive**: ใช้ถ้าข้อมูลโตเกินที่ D1 รับไหว (D1 จำกัดราว 10 GB ต่อฐานข้อมูล) หรืออยากได้ full-text search ที่แรงกว่า

## 3. เรื่องภาษาไทยที่ต้องวางแผนตั้งแต่ต้น

1. **ค้นหา**: ภาษาไทยไม่มีช่องว่างระหว่างคำ ตัวตัดคำมาตรฐานของ SQLite จึงหาคำกลางประโยคไม่เจอ แผนคือใช้ FTS5 แบบ `trigram` ค้นชื่อเรื่อง ชื่อนักเขียน และแท็ก **[ต้องเช็ก]** ว่า D1 รองรับ trigram tokenizer หรือไม่ ถ้าไม่รองรับ จะตัดคำตอนบันทึก (เช่นด้วย `Intl.Segmenter` ซึ่งมีใน Workers) แล้วเก็บลง FTS แทน
2. **ฟอนต์**: ใช้ฟอนต์ไทยที่อ่านยาวได้สบายตา เช่น Sarabun, Noto Sans Thai, IBM Plex Sans Thai และให้นักอ่านปรับขนาดตัวอักษร ระยะบรรทัด และโหมดกลางคืนได้
3. **URL**: ใช้ slug ภาษาอังกฤษหรือตัวเลข เช่น `/novel/123-ชื่อเรื่อง` เพื่อให้แชร์ลิงก์แล้วไม่เพี้ยน
4. **วันที่และเวลา**: แสดงตามเวลาไทย และเลือกได้ว่าจะแสดงเป็นปี พ.ศ.
5. **กฎหมาย**: ต้องทำนโยบายความเป็นส่วนตัวตาม **PDPA** และเนื่องจากรับเนื้อหา 18+ ต้องมีระบบเรตเนื้อหาและยืนยันอายุ (ดูหัวข้อ 3.1)

### 3.1 เนื้อหา 18+ และการอนุมัติโดย admin

- นักเขียนเลือกเรตเรื่องเป็น ทั่วไป / 13+ / 18+
- เรื่องที่ตั้งเป็น **18+ จะไม่ขึ้นเว็บทันที** สถานะจะเป็น `pending_review` จนกว่า admin จะกดอนุมัติหรือปฏิเสธ (พร้อมเหตุผล) และนักเขียนได้รับแจ้งผล
- **[สมมติฐาน]** อนุมัติครั้งเดียวที่ระดับเรื่อง ตอนใหม่ของเรื่องที่อนุมัติแล้วเผยแพร่ได้เลย แต่ admin ยังซ่อนตอนได้ทุกเมื่อ และถ้านักเขียนเปลี่ยนเรตจากทั่วไปเป็น 18+ ต้องเข้าคิวอนุมัติใหม่ (ถ้าอยากให้อนุมัติทุกตอน บอกได้ครับ)
- นักอ่านต้องล็อกอินและกรอกวันเกิดว่าอายุ 18 ปีขึ้นไปจึงจะเปิดอ่านเรื่อง 18+ ได้ คนที่ไม่ล็อกอินจะเห็นแค่ชื่อเรื่องพร้อมป้าย 18+
- เรื่อง 18+ ไม่ขึ้นหน้าแรกสำหรับคนที่ไม่ได้ล็อกอิน และตั้ง `noindex` ไม่ให้ Google เก็บ
- หน้า admin มีคิว "รออนุมัติ" และบันทึกว่าใครอนุมัติอะไรเมื่อไร

## 4. ฟีเจอร์แบ่งตามเฟส

### เฟส 0: วางรากฐาน (ประมาณ 1 สัปดาห์)
- สร้าง GitHub repo (รอ Maki ยืนยันชื่อและความเป็นส่วนตัว), ตั้ง Workers + D1 + R2 ทั้ง staging และ production
- CI/CD ด้วย GitHub Actions, ตั้งค่า lint และ test
- ตั้งชื่อแบรนด์ ทำโลโก้ และกำหนดโทนสีของเราเอง

### เฟส 1: MVP อ่านและเขียนได้ (ประมาณ 4–6 สัปดาห์)
- สมัคร/ล็อกอิน (อีเมล + Google + LINE), หน้าโปรไฟล์
- นักเขียน: สร้างเรื่อง (ชื่อ ปก เรื่องย่อ หมวด แท็ก เรต), เขียนตอนด้วย Tiptap, บันทึกร่าง, เผยแพร่, ตั้งเวลาเผยแพร่
- เรต 18+: ส่งเข้าคิวให้ admin อนุมัติ และให้นักอ่านยืนยันอายุก่อนอ่าน (หัวข้อ 3.1)
- นักอ่าน: หน้าแรก, หน้าหมวด, หน้าเรื่อง, หน้าอ่านตอน (ปรับฟอนต์และโหมดกลางคืนได้), ตอนก่อนหน้า/ถัดไป
- ชั้นหนังสือ (เก็บเรื่อง), ประวัติการอ่าน, จำว่าอ่านถึงตอนไหน
- กดถูกใจ, คอมเมนต์ระดับตอน
- ค้นหาจากชื่อเรื่อง นักเขียน และแท็ก
- Admin: คิวอนุมัติเรื่อง 18+, ซ่อนเรื่องหรือคอมเมนต์, ดูรายงาน
- SEO: meta tag, OpenGraph (ปกขึ้นเวลาแชร์ Facebook/LINE), sitemap

### เฟส 2: ชุมชนและการเติบโต (ประมาณ 3–4 สัปดาห์)
- ติดตามนักเขียน, แจ้งเตือนเมื่อตอนใหม่ออก (ในเว็บ + อีเมล)
- อันดับยอดนิยมรายวัน/สัปดาห์/เดือน แยกตามหมวด
- สถิตินักเขียน: ยอดวิว ยอดถูกใจ ผู้ติดตาม แยกตามตอน
- ระบบรายงานเนื้อหาและแบนผู้ใช้
- **นิยายแชท** (เล่าเป็นบทสนทนาแบบแชท) ถ้าต้องการ

### เฟส 3: รายได้ (เลื่อนออกไป Maki ให้อ่านฟรีก่อน)
- ระบบเหรียญ: เติมเหรียญด้วย PromptPay/บัตร, ใช้เหรียญปลดล็อกตอน, ซื้อทั้งเรื่องหรือ e-book
- บัญชีแยกประเภทแบบ ledger (ทุกการเพิ่มหรือลดเหรียญเป็นหนึ่งรายการ ห้ามแก้ยอดตรงๆ) เพื่อกันยอดเพี้ยนและตรวจสอบย้อนหลังได้
- ส่วนแบ่งรายได้นักเขียน, หน้าขอถอนเงิน, ยืนยันตัวตนนักเขียน (KYC)
- ใบเสร็จ/ใบกำกับภาษี

### ภายหลัง
- PWA ให้ติดตั้งบนมือถือและอ่านแบบออฟไลน์, แอปมือถือ, ระบบแนะนำเรื่อง

## 6. ค่าใช้จ่ายโดยประมาณ

- ผู้ใช้ไม่เกิน 100 คน: **Workers Free น่าจะพอ** (100,000 request/วัน) เพราะตัด Queues ออกแล้ว ค่อยอัปเป็น Workers Paid $5/เดือน ถ้าโตขึ้น
- D1, R2, KV: มีโควตาฟรีที่น่าจะพอในช่วงแรก **[ต้องเช็ก]** ตัวเลขล่าสุดในหน้า pricing ของ Cloudflare ก่อนเปิดตัว
- โดเมน: ประมาณ 300–1,000 บาท/ปี (.com หรือ .co.th)

## 7. คำถามที่ยังเหลือ

ตอบแล้ว: ระบบเหรียญ (ยังไม่ทำ), จำนวนผู้ใช้ (ไม่เกิน 100), 18+ (รับ ต้องให้ admin อนุมัติ), คนเขียนโค้ด (Claude) และ GitHub (ต้องการ)

1. **GitHub repo**: ใช้ชื่ออะไร (เสนอ `readable`) และเป็น private หรือ public (เสนอ private) Maki ต้องสร้าง repo เปล่าบน GitHub เอง แล้วบอกผม ผมจะเชื่อมต่อและ push ให้
2. **การอนุมัติ 18+**: อนุมัติครั้งเดียวต่อเรื่องตามที่เสนอไว้ในหัวข้อ 3.1 ได้ไหม
3. **ภาษา**: ไทยอย่างเดียว หรือต้องมีอังกฤษด้วย
4. **ประเภทเนื้อหา**: นิยายข้อความอย่างเดียว หรือรวมนิยายแชท การ์ตูน/รูปภาพ ด้วย
5. **ชื่อและโดเมน**: ใช้ชื่อ "readable" ไหม มีโดเมนแล้วหรือยัง
6. **บัญชี Cloudflare**: มีแล้วหรือยัง และอยากเปิด MVP ภายในเมื่อไร

## 8. ขั้นถัดไป

1. Maki สร้าง GitHub repo ตามชื่อและแบบที่ตกลงกัน แล้วบอกผม
2. ผม scaffold โปรเจกต์ React Router + D1 + Drizzle แล้วเปิด PR แรก จากนั้น deploy หน้า "Hello" ขึ้น Workers เพื่อพิสูจน์ว่าทุกส่วนต่อกันได้ (Maki ต้องเชื่อม Cloudflare กับ GitHub Actions ด้วย API token)
3. ทดสอบเรื่อง **[ต้องเช็ก]** ทั้งหมด โดยเฉพาะการค้นหาภาษาไทยใน D1
4. เริ่มเฟส 1 โดยเปิด PR ทีละฟีเจอร์ให้ Maki ตรวจ
